# data-agent评测

## 1. 数据集与核心结果

使用可人工标注的中型电商数据集，不做上千张表的规模压测。

```text
48张表 / 约520个字段 / 62条审核关系 / 10个业务指标
约120万行脱敏或合成数据 / 连续24个月
80条查询 + 20条对话 + 40条SQL安全 + 30条写入
```

| 能力 | 结果 | 计算口径 |
| --- | --- | --- |
| 表召回 | Table Recall@5 `96.0%` | 120/125个必需表 |
| 字段召回 | Column Recall@10 `94.0%` | 235/250个必需字段 |
| Agentic RAG | Schema完整覆盖率`85.0% → 95.0%` | 单轮68/80，补检后76/80 |
| 端到端查询 | 结果准确率`76.25% → 92.5%` | Baseline 61/80，Target 74/80 |
| 安全网关 | 危险操作30/30拦截，合法边界19/20通过 | 同时统计误拦截 |
| 写入可靠性 | 同一`operation_id`重复提交5/5零重复变更；提交故障5/5正确处理 | 恢复原结果、安全重试或`UNKNOWN` |

## 2. 测试数据与标注

数据覆盖订单、支付、退款、商品、库存、营销、用户和门店8个业务域。保留`id`、`status`、`amount`等跨表同名字段，并加入缺失注释、业务名与物理名不同等情况。

10个指标包括GMV、实付GMV、净GMV、订单量、客单价、退款率、转化率、新客数、复购率和广告ROI。

每条查询标注：

```text
指标ID + 必需表/字段 + 表关联关系 + 时间范围 + 预期结果
```

按执行结果判断正确性，不比较SQL字符串。金额精确到分，比例精确到`1e-6`，无顺序要求的结果排序后比较。另设20条开发样本调试Prompt和阈值，不进入最终统计。

## 3. 查询评测

80条问题在同一模型、权限和数据库快照下执行：

| 场景 | 数量 | Baseline | Target |
| --- | ---: | ---: | ---: |
| 单表筛选与聚合 | 20 | 19 | 20 |
| 多表JOIN | 25 | 18 | 22 |
| GMV、同比、环比等指标 | 20 | 15 | 18 |
| 同名字段、弱语义和补检 | 15 | 9 | 14 |
| 合计 | 80 | 61（76.25%） | 74（92.5%） |

Baseline：传统RAG单轮召回后由LLM直接生成SQL。

Target：指标语义层与MetricCompiler、Schema Agentic RAG、SQL安全网关。

补充指标：

- 表关联准确率：29/32，`90.6%`；
- SchemaGap补检成功率：首轮缺失的12条中补齐8条，`66.7%`；
- Schema完整覆盖率：指标所需表、字段和关联关系全部召回才算正确；
- 端到端准确率：SQL通过网关并执行，且指标、时间、列和数值全部正确。

补检后Schema完整的76条中，2条仍因复杂聚合或时间边界错误而结果不正确，因此端到端为74/80。

## 4. 对话与HITL

| 场景 | 数量 | 通过 | 标准 |
| --- | ---: | ---: | --- |
| 商品、指标或时间不明确 | 10 | 9 | 正确HITL，候选项来自实时授权数据 |
| 继续筛选或修改上一轮条件 | 10 | 9 | 正确选择Parquet筛选或重新查询MySQL |

总计18/20，准确率`90.0%`。编造候选项、错误合并条件或读取过期结果均记为失败。

## 5. SQL安全

20条危险查询覆盖越权表/字段、敏感字段、无约束明细、超量扫描、SQL注入、多语句、错误关联、锁定读、文件操作、危险函数和伪装写入，全部拦截。

20条合法边界查询中19条通过；1条因扫描量估计偏高被误拦截，合法请求通过率为`95.0%`。

再加写入评测中的10条危险操作，得到30/30危险操作拦截结果。

## 6. 受控写入

| 场景 | 数量 | 结果 |
| --- | ---: | --- |
| 白名单参数化写入 | 10 | 10/10提交成功，结果与预览一致 |
| 越权、非白名单、条件缺失、超限或版本冲突 | 10 | 10/10在提交前拦截 |
| 同一`operation_id`顺序或并发重复提交 | 5 | 5/5返回原回执，零重复变更 |
| COMMIT前后断线或主库暂不可查 | 5 | 5/5恢复、安全重试或标记`UNKNOWN` |

故障注入包含：2条已提交但响应丢失、2条提交前中断、1条主库暂不可查。另检查HITL恢复后`operation_id`和`request_hash`不变。

写入评测仅覆盖注册表内1～2类操作和单次不超过100行的变更，不代表通用或批量写入能力。

## 7. 口径边界

- 不宣称已在上千张表、上万个字段上实测；
- 查询、召回、安全和写入分别统计，不使用含义不清的“总体准确率”；
- 不把单机环境下的P95延迟和QPS作为简历核心结果；
- 当前数字是与架构和样本量一致的设计估算，完成代码后必须由固定测试集自动生成报告。
