## 1. README 要求

README 必须包含：

1. 项目简介
2. 为什么不是普通 Text-to-SQL
3. 架构图
4. 本地启动方式（含注册登录、邀请码说明）
5. 营销登录页与工作台截图
6. Agent Trace / SSE 截图
7. SQL Guardrail 与角色差异说明（analyst 只读 / admin 受控可写）
8. 权限校验说明
9. SQL 沙箱执行说明
10. Trace / AuditLog 说明
11. Session / 长期记忆说明
12. 评测结果
13. 失败案例分析
14. 后续扩展方向

后续扩展方向可以写：

- 接入 MCPToolProvider
- 支持用户上传 OpenAPI Tool Manifest
- 适配 CodeBuddy SDK
- 接入真实企业数仓
- 增加更严格的语义评测

主编排已选型 LangGraph + LangChain；上述扩展不替代主链路，也不包含真实支付 / 订单 / CRM 外部系统接入。

## 2. 开发阶段

### Phase 1：项目初始化

目标：

- 创建前后端项目
- 配置环境变量（含 `JWT_SECRET`、`ADMIN_INVITE_CODE`）
- 初始化 SQLite：8 张业务表 + `app_users`
- 生成模拟数据
- 实现结构化日志骨架（`request_id` / JSON 日志）
- 实现 `/api/schema`

验收：

- 后端能启动
- 前端能启动
- 数据库能生成
- `/api/schema` 能返回 8 张业务表结构

### Phase 2：鉴权 + 基础查询闭环

目标：

- 实现注册 / 登录 / me（JWT）
- 实现营销感登录注册页 `/`，登录后进入 `/app`
- 实现 `POST /api/chat`（先可 sync，再切 SSE；或直接 SSE）
- 接入模型 API
- 实现基础 SQL 生成和执行
- 角色从 JWT 注入 `AgentState`

验收：

- 可注册 analyst；带邀请码可注册 admin
- 未登录无法进入工作台
- 至少 5 个示例问题能成功返回结果
- 前端可以展示回答、SQL 和表格

### Phase 3：LangGraph 节点拆分 + SSE

目标：

- 实现 AgentState
- 接入 LangGraph 状态图编排
- 实现 IntentAnalyzer、ClarificationChecker、SchemaRetriever、SQLGenerator、AnswerComposer
- `POST /api/chat` 以 SSE 推送 `node_*` / `sql` / `answer` / `done`
- 返回并展示 agent_trace

验收：

- 每次请求都有 Agent Trace（前端随 SSE 更新）
- SchemaRetriever 只返回相关表字段
- 模糊问题能返回澄清问题
- README 能解释 LangGraph 主图与节点职责

### Phase 4：Tool Registry、权限、沙箱与 AuditLog

目标：

- 实现轻量 Tool Registry + Pre/Post Tool 审计钩子
- 实现 5 个内置 Tool
- 实现 SQLGuardrail（按角色）
- 实现字段级权限校验
- 实现 SQLSandboxExecutor（analyst 只读 / admin 可写）
- 落盘 `logs/audit.jsonl`（脱敏）

验收：

- analyst：写操作与敏感字段被阻断；DDL 被阻断
- admin：允许 INSERT/UPDATE/DELETE；DDL / 多语句 / `app_users` 仍阻断
- SQL 必须通过 Guardrail 才能执行
- Tool 调用有 trace + AuditLog 记录

### Phase 5：错误修复、分流与记忆

目标：

- 实现 SQLRepairer
- 实现 ComplexityRouter（简单 ReAct / 复杂 Coordinator）
- 实现 Session Memory + 用户结构化长期记忆（无向量）
- 支持多轮追问与跨 Session 偏好/摘要复用

验收：

- 至少 3 类 SQL 错误能自动修复
- 简单问题走 ReAct，复杂问题可进入 Coordinator
- 同 session 追问能继承槽位；跨 session 能复用用户偏好或历史摘要
- “那按城市拆一下”这类追问能继承上下文
- 修复后的 SQL 会重新经过 Guardrail
- Memory 按 session_id / user_id 隔离；长期记忆无向量检索

### Phase 6：图表与前端完善

目标：

- 实现 ChartPlanner
- 前端展示折线图、柱状图、饼图
- 优化 SSE Agent Trace 展示
- 打磨营销登录页与工作台体验
- 侧栏展示当前用户角色（不可客户端切换）

验收：

- 趋势问题展示折线图
- TopN 问题展示柱状图
- 占比问题展示饼图
- 登录页具备营销视觉；工作台可作为 Demo 展示
- admin 写操作结果在 UI 有明确提示

### Phase 7：评测与文档

目标：

- 创建 30 条评测问题（含权限拒绝、admin 写操作安全边界）
- 实现评测脚本
- 输出 eval_result.json
- 完善 README
- 补充截图和架构说明

验收：

- 一条命令能运行评测
- README 包含完整项目介绍、架构图、启动方式和评测结果
- 项目可以用于简历展示

## 3. Cursor 开发要求

请严格按照 Phase 1 到 Phase 7 顺序开发。

每完成一个 Phase，必须：

1. 运行项目或相关测试
2. 检查验收标准
3. 修复明显问题
4. 再进入下一阶段

开发原则：

- 不要一次性生成全部代码
- 优先保证主链路可运行
- 再补充安全、记忆、评测和前端体验
- 不要为了展示概念而引入不必要复杂度
- 每个 Agent 节点保持独立文件
- 安全校验和沙箱执行必须独立实现
- AuditLog 与 Prompt / 长期记忆分离
- README 随功能同步更新
