# Spec 模板：能力名称

状态：`Draft`

对应里程碑：Mx

## 1. 范围

用 2 到 4 句话说明这个能力解决什么问题，以及它在系统链路中的位置。

## 2. In Scope

- 本 spec 必须实现的能力。
- 必须支持的正常路径。
- 必须覆盖的安全、权限、预算或持久化边界。

## 3. Out of Scope

- 本阶段明确不做的能力。
- 后续阶段才做的能力。
- 不能被误认为本 spec 负责的旁路。

## 4. 输入输出

输入示例：

```json
{}
```

输出示例：

```json
{}
```

拒绝或异常示例：

```json
{
  "status": "REJECTED",
  "error_code": "ERROR_CODE",
  "retryable": false
}
```

## 5. 不变量

- 必须永远成立的规则。
- 权限和安全边界。
- 不能被 LLM、用户确认或重试覆盖的约束。

## 6. Trace 字段

- `trace_id`
- 关键输入 ID。
- 关键版本。
- 决策结果。
- 错误码。
- 耗时。

## 7. 验收标准

- 可从用户可见行为或测试结果判断的完成条件。
- 不使用“基本可用”“尽量”“优化”等模糊表述。

## 8. 测试证据

- 单元测试。
- 集成测试。
- 安全或越权测试。
- 评测用例。
- Trace 或报告样本。
