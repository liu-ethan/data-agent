# 评测体系

> 返回 [需求文档索引](./需求文档.md)

## 1. 评测集位置

```text
backend/app/eval/questions.json
```

不少于 30 条评测问题。

## 2. 单条格式（单轮）

```json
{
  "id": "q001",
  "question": "上个月 GMV 最高的 5 个渠道是什么？",
  "category": "aggregation",
  "user_role": "analyst",
  "must_include_tables": ["orders"],
  "expected_columns": ["channel", "gmv"],
  "expected_route_mode": "react",
  "difficulty": "medium"
}
```

`expected_route_mode` 可选；有则用于检查分流是否合理（允许与规则覆盖后的最终 `route_mode` 对比）。

## 3. 多轮格式

多轮追问用同一 `session_id` 顺序执行；条目可用 `turns` 数组：

```json
{
  "id": "q_multi_01",
  "category": "multi_turn",
  "user_role": "analyst",
  "turns": [
    {
      "question": "最近 30 天各渠道 GMV 怎么样？",
      "must_include_tables": ["orders"]
    },
    {
      "question": "那只看华东地区呢？",
      "must_include_tables": ["orders"],
      "expect_slot_inherit": ["metrics", "time_range", "group_by"],
      "expect_filter_contains": ["华东"]
    }
  ]
}
```

评测脚本应按 turn 顺序调用 Agent（共享 session），检查后轮是否继承槽位且 SQL/过滤体现追问约束。第一版对 `expect_filter_contains` 可用 SQL 文本或中间槽位做包含判断，不强求语义等价。

## 4. 覆盖类别

建议包含：聚合、JOIN、TopN、时间窗口、多轮追问、权限拦截（敏感字段 / 写操作）、admin 受控写、危险 SQL（DDL / 多语句）、分流（react / coordinator）抽样。

## 5. 评测指标

- execution_success_rate
- repair_success_rate
- schema_hit_rate
- permission_block_success_rate
- average_latency_ms
- （可选）route_match_rate：在标注了 `expected_route_mode` 的样本上统计

## 6. 输出文件

```text
backend/app/eval/eval_result.json
```

## 7. 说明

- 第一版不强求自动判断语义完全正确
- 优先评估是否可执行、是否命中相关表、是否遵守权限、多轮是否继承槽位
- analyst 用例应验证写操作与敏感字段（`users.name/phone/email/id_card`）被拦截；admin 用例应验证业务写可用且 DDL / 应用表仍拦截
- README 中展示评测结果表
