# 接口与前端

> 返回 [需求文档索引](./需求文档.md)

## 1. 后端接口

鉴权：除注册/登录外，受保护接口均需 `Authorization: Bearer <JWT>`。  
角色以服务端用户记录为准，**禁止**客户端自报 `user_role`。

### 1.1 POST /api/auth/register

注册应用账号。

请求：

```json
{
  "username": "alice",
  "password": "********",
  "role": "analyst",
  "invite_code": null
}
```

规则：

- `role` 为 `analyst` 时无需邀请码
- `role` 为 `admin` 时必须提供 `invite_code`，并与 `config.yaml` 中 `backend.admin_invite_code` 校验
- 密码哈希存储；不返回明文密码

响应：与登录同形——注册成功后**直接签发 JWT**（含 `access_token` / `token_type` / `user`，不含密码）。

### 1.2 POST /api/auth/login

请求：

```json
{
  "username": "alice",
  "password": "********"
}
```

响应：

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer",
  "user": {
    "id": "u_1",
    "username": "alice",
    "role": "analyst"
  }
}
```

### 1.3 GET /api/auth/me

校验 JWT，返回当前用户。

### 1.4 POST /api/chat（SSE 流式）

请求头：

- `Authorization: Bearer <JWT>`
- `Accept: text/event-stream`

请求体：

```json
{
  "question": "上个月 GMV 最高的 5 个渠道是什么？",
  "session_id": "sess_a1b2c3d4e5f6"
}
```

`session_id` 由前端传入；后端经 Memory `ensure_session` 处理：会话不存在则按当前用户创建，已存在但 `user_id` 不匹配则拒绝。工作台使用「当前选中会话」的 id（`POST /api/sessions` 新建或列表既有项）；同一浏览器切换账号时勿复用其他用户的 `session_id`。

响应：`Content-Type: text/event-stream`

按节点 / 片段推送事件。建议事件类型：

| event | 含义 |
|-------|------|
| `run_start` | 开始一次分析，携带 `request_id` / `trace_id` |
| `node_start` | 某 LangGraph 节点开始 |
| `node_end` | 节点结束，附简要 summary |
| `route_decision` | 分流结果：`route_mode`（react/coordinator）与 `route_source`（model/rule_override） |
| `tool_start` / `tool_end` | Tool 调用前后（与后端 AuditLog 对齐） |
| `sql` | 生成或修复后的 SQL |
| `rows` | 查询结果（可截断预览） |
| `chart` | 图表配置 `{type, x, y, title}`（由 ChartPlanner 在 Executor 成功后产出；写操作或空结果不推送） |
| `write_result` | admin 写操作成功：`{affected_rows, sql}`（仅 `SQLExecutor` 且 `is_write=true` 时推送） |
| `answer` / `token` | 分析结论（可整段或 token 流） |
| `session_title` | MemorySave 首次写入会话标题后推送 `{session_id, title}`（`title` ≤10 字） |
| `error` | 可展示错误（已脱敏），附 `message` / `request_id` / `trace_id` 便于排查 |
| `done` | 结束，附 `latency_ms`、`repaired`、`need_clarification` 等汇总；`repaired=true` 表示曾触发 Repairer（是否最终成功见 `error` / 结果事件），即 `done.repaired` |

示例：

```text
event: run_start
data: {"request_id":"req_xxx","trace_id":"tr_xxx","session_id":"sess_xxx"}

event: node_start
data: {"node":"IntentAnalyzer"}

event: node_end
data: {"node":"IntentAnalyzer","summary":"识别为渠道销售分析"}

event: sql
data: {"sql":"SELECT ...","repaired":false}

event: chart
data: {"type":"bar","x":"channel","y":"gmv","title":"上月各渠道 GMV Top5"}

event: done
data: {"latency_ms":1234,"need_clarification":false,"clarification_question":null,"repaired":false}
```

说明：

- `user_role` 从 JWT 解析后写入 `AgentState`
- 前端按事件渐进渲染 Trace、SQL、表、图、结论；多轮工作台将事件写入**当前轮** `TurnCard`，不覆盖历史轮
- 评测或脚本可用内部 sync 调用；可选提供 `POST /api/chat/sync` 返回完整 JSON（非 Demo 主路径）

### 1.5 GET /api/examples

返回示例问题列表（需登录）。

### 1.6 GET /api/schema

返回业务表结构和字段说明（**仅业务表，不含应用表**）。需登录。

- `analyst`：隐藏敏感字段元数据（`users.name` / `phone` / `email` / `id_card`）
- `admin`：可见全部业务字段元数据

### 1.7 Sessions API

路由前缀 `/api/sessions`；仅返回 / 操作当前 JWT 用户的会话。

**GET /api/sessions**

```json
{
  "sessions": [
    {
      "id": "sess_xxx",
      "title": "最近 30 天 GMV 趋势",
      "updated_at": "2026-07-26 11:00:00",
      "turn_count": 2
    }
  ]
}
```

按 `updated_at` 降序。

**POST /api/sessions**

创建空会话；服务端生成唯一 id（形如 `sess_<uuid>`），写入 `chat_sessions`。

响应与列表项同形，例如：

```json
{
  "id": "sess_xxx",
  "title": null,
  "updated_at": "2026-07-26 11:00:00",
  "turn_count": 0
}
```

**DELETE /api/sessions/{session_id}**

硬删除会话及其全部 `session_turns`；成功 → **204** 无响应体。

- 会话不存在或不属于当前用户 → **404**，`detail`: `"Session not found"`

**GET /api/sessions/{session_id}/turns**

```json
{
  "session_id": "sess_xxx",
  "turns": [
    {
      "turn_index": 1,
      "question": "...",
      "intent": "...",
      "sql_text": "...",
      "result_summary": "...",
      "metrics": [],
      "time_range": null,
      "filters": {},
      "group_by": [],
      "display": {
        "columns": ["order_date", "order_count", "gmv"],
        "rows": [{"order_date": "2026-06-26", "order_count": 3, "gmv": 0}],
        "chart": {
          "type": "line",
          "x": "order_date",
          "y": "order_count",
          "series": ["order_count", "gmv"],
          "title": "每日订单量与 GMV"
        },
        "sql_repaired": false,
        "guardrail_passed": true,
        "trace": [{"event": "node_end", "summary": "SQLGuardrail: passed"}]
      },
      "created_at": "..."
    }
  ]
}
```

- 校验会话归属；不存在或不属于当前用户 → **404**
- 返回最近 N 轮（与 Memory 一致，默认 **10**），按 `turn_index` 升序
- `display`：前端展示载荷（`columns` / `rows`≤100 / `chart` / `trace` / 校验标记）；写轮时由 Memory 持久化
- 若历史轮仅有 `sql_text` 而无 `display.rows`：服务端经 Guardrail + 沙箱重执行 SQL，并用 ChartPlanner 启发式补齐图表后回写 `display_json`

**标题**：首轮任意完成并写入 `session_turns` 后，若 `chat_sessions.title` 为空，由 LLM 生成 ≤10 字摘要写入 title（LLM 失败则回退为首问截断 ≤10）；仅写一次；成功后经 SSE 推送 `session_title` 并刷新 `updated_at`（MemorySave 路径）。

### 1.8 Tables API

路由前缀 `/api/tables`；只读、确定性查询，不走 LLM / Tool Registry，不写 AuditLog。

**GET /api/tables**

```json
{
  "tables": [
    { "name": "orders", "column_count": 9, "row_count": 1280 }
  ]
}
```

仅 `BUSINESS_TABLES`；`column_count` 对 `analyst` 不含敏感列（与 `/api/schema` 一致）。

**GET /api/tables/{name}?page=1&page_size=50**

```json
{
  "name": "orders",
  "columns": [{ "name": "id", "type": "INTEGER", "nullable": false }],
  "page": 1,
  "page_size": 50,
  "total_rows": 1280,
  "rows": [{ "id": 1, "order_date": "..." }]
}
```

- `name` 不在业务表白名单 → **404**
- `page_size` 固定 **50**：客户端传入其它值时服务端仍按 50 查询并在响应中返回 `page_size: 50`
- `analyst` 访问 `users` 时不返回敏感列的数据与元数据

### 1.9 POST /api/eval/run

运行评测集，返回评测指标（需登录；建议仅 admin 或本地开发开放）。

## 2. 前端页面

### 2.0 路由

| 路径 | 说明 |
|------|------|
| `/` | 营销感 **登录 / 注册** 页（品牌 + AI 卖点 + 能力故事 + 表单） |
| `/app` | 登录后多轮工作台；未登录重定向到 `/` |
| `/app/tables` | 登录后业务表浏览（概览 + 分页行）；未登录重定向到 `/` |

受保护路由使用 `ProtectedRoute`，与 `/app` 相同 JWT 守卫。

### 2.1 营销登录 / 注册页（`/`）

要求：

- 品牌名 **data-analysis-agent** 为第一视口主信号
- 一句价值主张（自然语言 → 安全 SQL → 结论 / 表 / 图）
- **四宫格 AI 卖点**（示例）：NL → 安全 SQL；双路径编排（ReAct / Coordinator）；SSE Trace；多轮记忆
- **QueryTicker**：轮播「问句 → SQL → Guardrail 通过」示意，强化可观测与安全执行
- 登录 / 注册表单：注册可选 `analyst`（默认）或 `admin`（需邀请码）；保留 demo 账号说明
- 登录成功后进入 `/app`
- 首屏下方可滚动 **能力故事**（三段）：理解（意图 + 槽位 / 澄清）→ 执行（Schema Linking → 权限 → 沙箱 → 可修复）→ 交付（结论 · 表 · 图 · Trace；多轮追问）
- 视觉为营销落地页气质（大气氛围），非仪表盘堆砌；与工作台视觉可成体系但不必同一套组件皮肤

### 2.2 工作台布局（`/app`）

**左侧（SessionSidebar）**

- 项目名 data-analysis-agent + 简短说明
- 当前用户：username + role（只读，不可客户端改角色）
- **会话区**：「+ 新建」；列表项展示 title（空则占位 **「新会话」**）与更新时间；点击切换会话；每项可 **删除**（确认后硬删；删当前会话则切到其余会话或自动新建）
- 按钮 **「查看全部数据表」** → `/app/tables`
- 退出登录
- **不在侧栏展示**完整业务表名 + 行数列表（改由数据表页承载）

**右侧（时间线 + 输入）**

- **主区空态**（无 turns 且非加载中）：展示示例问题列表（`GET /api/examples`）；点击**仅填入**底部输入框，不自动发送；一旦有 turns 则隐藏空态
- `turns[]` 垂直时间线：用户问题右对齐气泡；Agent 左对齐 **TurnCard**
- 每轮 TurnCard 含：分析结论（可流式）、独立折叠 chips（**SQL** / **查询结果** / **图表** / **AGENT TRACE**）、写操作提示、澄清、错误、耗时等
- SQL 区在通过校验后展示文案：**已通过权限校验 / 沙箱检查 / 安全审核**
- 当前流式轮：结论、SQL、查询结果、图表默认展开；AGENT TRACE 默认可折叠
- 历史轮：映射 `display`（含重执行补齐后的 rows/chart/trace）；结论仍可用 `result_summary`
- 多指标趋势图：`chart.series` 可含多条折线；量纲差异大时双 Y 轴
- 底部固定：多行输入 +「分析」；提交 **append 新轮**，不清空既有 turns
- `POST /api/chat` 的 `session_id` 为当前选中会话 id

**会话生命周期**

- 新建：`POST /api/sessions` → 设为当前 → 清空 turns
- 切换：加载 `GET /api/sessions/{id}/turns`（含 `display`）映射为完整可展示 turns
- 删除：`DELETE /api/sessions/{id}`；侧栏确认后调用；删当前会话时切到列表首项或新建空会话
- 进入 `/app` 时若无会话则自动 `POST /api/sessions` 创建一个；刷新后以服务端会话列表与 turns 为准
- 流式过程中监听 `session_title`，更新侧栏与顶栏标题

### 2.3 数据表页（`/app/tables`）

- 顶栏：标题 + **「返回工作台」** → `/app`
- 默认：业务表概览（name、column_count、row_count）
- 选中表：可折叠字段说明 + 分页表格；`page_size` 固定 50；上一页 / 下一页 / 页码
- 只读；敏感列规则与 `/api/schema`、`GET /api/tables/{name}` 一致

### 2.4 交互与 SSE 展示要求

- **主区空态**展示示例问题；点击仅填入输入框（不自动提交）；有 turns 后不显示空态
- 消费 `session_title` 更新当前会话在侧栏与顶栏的 title
- 提交后建立 SSE，按事件更新**当前轮** UI（不必等全部结束才渲染）
- SQL 通过校验时显示「已通过安全校验」
- SQL 自动修复时显示「已根据执行错误自动修复」（结合 `done.repaired` 与 `sql.repaired`）
- 权限拒绝时显示清晰提示
- 模糊问题时展示澄清问题
- admin 写操作成功/失败有明确提示，并在 Trace 中标记高风险
- 图表：消费 SSE `chart`，用 Recharts 渲染 `line` / `bar` / `pie`；`table` 类型不渲染图形
- admin 写操作成功区：消费 `write_result`，展示「写操作已成功执行 · 影响 N 行」

## 3. 示例问题

内置至少 15 个示例问题。

1. 上个月 GMV 最高的 5 个渠道是什么？
2. 最近 30 天每天的订单量和 GMV 趋势如何？
3. 哪些商品品类的退款率最高？
4. 各城市的新用户注册数排名如何？
5. 最近一个季度客单价最高的商品类别是什么？
6. 不同支付方式的支付成功率是多少？
7. 活动期间各渠道转化率有什么变化？
8. 哪些商品销量高但利润率低？
9. 本月退款金额最高的原因有哪些？
10. 华东地区最近 7 天的订单趋势如何？
11. 新用户和老用户的消费金额差异如何？
12. 各渠道访问到下单的转化率是多少？
13. 最近 90 天复购用户贡献了多少 GMV？
14. 哪些城市订单量增长最快？
15. 本月退款率相比上月是否升高？

可为 admin 额外准备 1–2 个写操作示例（如更新某活动预算），用于演示受控写权限。
