## 1. 后端接口

鉴权：除注册/登录外，受保护接口均需 `Authorization: Bearer <JWT>`。  
角色以服务端用户记录为准，**禁止**客户端自报 `user_role`。

### 1.1 POST /api/auth/register

注册应用账号。

请求：

```json
{
  "username": "alice",
  "password": "********",
  "role": "analyst",
  "invite_code": null
}
```

规则：

- `role` 为 `analyst` 时无需邀请码
- `role` 为 `admin` 时必须提供 `invite_code`，并与 `config.yaml` 中 `backend.admin_invite_code` 校验
- 密码哈希存储；不返回明文密码

响应：与登录同形——注册成功后**直接签发 JWT**（含 `access_token` / `token_type` / `user`，不含密码）。

### 1.2 POST /api/auth/login

请求：

```json
{
  "username": "alice",
  "password": "********"
}
```

响应：

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer",
  "user": {
    "id": "u_1",
    "username": "alice",
    "role": "analyst"
  }
}
```

### 1.3 GET /api/auth/me

校验 JWT，返回当前用户。

### 1.4 POST /api/chat（SSE 流式）

请求头：

- `Authorization: Bearer <JWT>`
- `Accept: text/event-stream`

请求体：

```json
{
  "question": "上个月 GMV 最高的 5 个渠道是什么？",
  "session_id": "default-1"
}
```

`session_id` 由前端传入，后端会校验其归属当前 JWT 用户（已存在且 `user_id` 不匹配则拒绝）。同一浏览器切换账号时勿复用其他用户的 `session_id`；工作台默认使用 `default-<user_id>`。

响应：`Content-Type: text/event-stream`

按节点 / 片段推送事件。建议事件类型：

| event | 含义 |
|-------|------|
| `run_start` | 开始一次分析，携带 `request_id` / `trace_id` |
| `node_start` | 某 LangGraph 节点开始 |
| `node_end` | 节点结束，附简要 summary |
| `route_decision` | 分流结果：`route_mode`（react/coordinator）与 `route_source`（model/rule_override） |
| `tool_start` / `tool_end` | Tool 调用前后（与后端 AuditLog 对齐） |
| `sql` | 生成或修复后的 SQL |
| `rows` | 查询结果（可截断预览） |
| `chart` | 图表配置 `{type, x, y, title}`（由 ChartPlanner 在 Executor 成功后产出；写操作或空结果不推送） |
| `write_result` | admin 写操作成功：`{affected_rows, sql}`（仅 `SQLExecutor` 且 `is_write=true` 时推送） |
| `answer` / `token` | 分析结论（可整段或 token 流） |
| `error` | 可展示错误（已脱敏），附 `message` / `request_id` / `trace_id` 便于排查 |
| `done` | 结束，附 `latency_ms`、`repaired`、`need_clarification` 等汇总；`repaired=true` 表示曾触发 Repairer（是否最终成功见 `error` / 结果事件），即 `done.repaired` |

示例：

```text
event: run_start
data: {"request_id":"req_xxx","trace_id":"tr_xxx","session_id":"default-1"}

event: node_start
data: {"node":"IntentAnalyzer"}

event: node_end
data: {"node":"IntentAnalyzer","summary":"识别为渠道销售分析"}

event: sql
data: {"sql":"SELECT ...","repaired":false}

event: chart
data: {"type":"bar","x":"channel","y":"gmv","title":"上月各渠道 GMV Top5"}

event: done
data: {"latency_ms":1234,"need_clarification":false,"clarification_question":null,"repaired":false}
```

说明：

- `user_role` 从 JWT 解析后写入 `AgentState`
- 前端按事件渐进渲染 Trace、SQL、表、图、结论
- 评测或脚本可用内部 sync 调用；可选提供 `POST /api/chat/sync` 返回完整 JSON（非 Demo 主路径）

### 1.5 GET /api/examples

返回示例问题列表（需登录）。

### 1.6 GET /api/schema

返回业务表结构和字段说明（**仅业务表，不含应用表**）。需登录。

- `analyst`：隐藏敏感字段元数据（`users.name` / `phone` / `email` / `id_card`）
- `admin`：可见全部业务字段元数据

### 1.7 POST /api/eval/run

运行评测集，返回评测指标（需登录；建议仅 admin 或本地开发开放）。

## 2. 前端页面

### 2.0 路由

| 路径 | 说明 |
|------|------|
| `/` | 营销感 **登录 / 注册** 页（品牌主导视觉，非工作台） |
| `/app` | 登录后工作台；未登录重定向到 `/` |

### 2.1 营销登录 / 注册页（`/`）

要求：

- 品牌名 data-analysis-agent 为第一视口主信号
- 一句价值主张 + 登录/注册表单
- 注册可选角色：默认 `analyst`；选 `admin` 时出现邀请码输入框
- 登录成功后进入 `/app`
- 视觉按营销落地页气质设计（大气氛围、非仪表盘堆砌）；工作台视觉可另成体系

### 2.2 工作台左侧区域（`/app`）

包含：

- 项目名称：data-analysis-agent
- 简短说明：企业经营数据分析 Agent
- 当前用户：username + role（只读展示，不可客户端改角色）
- 示例问题列表
- 数据表列表
- 退出登录

### 2.3 工作台右侧区域

包含：

- 自然语言输入框
- Agent 回答（SSE 渐进展示）
- SQL 展示区
- 查询结果表格（写操作可展示 `affected_rows`）
- 图表区域：基于 SSE `chart` 事件用 Recharts 渲染 `line`（趋势）/ `bar`（TopN、分类对比）/ `pie`（占比）；`table` 类型不渲染图形
- admin 写操作成功提示区：消费 `write_result` 事件，展示「写操作已成功执行 · 影响 N 行」
- Agent Trace 折叠面板（与 SSE `node_*` / `tool_*` 事件同步）

### 2.4 交互要求

- 点击示例问题自动填入输入框
- 提交后建立 SSE，按事件更新 UI（不必等全部结束才渲染）
- SQL 通过校验时显示“已通过安全校验”
- SQL 自动修复时显示“已根据执行错误自动修复”
- 权限拒绝时显示清晰提示
- 模糊问题时展示澄清问题
- admin 执行写操作成功/失败有明确提示，并在 Trace 中标记高风险

## 3. 示例问题

内置至少 15 个示例问题。

1. 上个月 GMV 最高的 5 个渠道是什么？
2. 最近 30 天每天的订单量和 GMV 趋势如何？
3. 哪些商品品类的退款率最高？
4. 各城市的新用户注册数排名如何？
5. 最近一个季度客单价最高的商品类别是什么？
6. 不同支付方式的支付成功率是多少？
7. 活动期间各渠道转化率有什么变化？
8. 哪些商品销量高但利润率低？
9. 本月退款金额最高的原因有哪些？
10. 华东地区最近 7 天的订单趋势如何？
11. 新用户和老用户的消费金额差异如何？
12. 各渠道访问到下单的转化率是多少？
13. 最近 90 天复购用户贡献了多少 GMV？
14. 哪些城市订单量增长最快？
15. 本月退款率相比上月是否升高？

可为 admin 额外准备 1–2 个写操作示例（如更新某活动预算），用于演示受控写权限。
