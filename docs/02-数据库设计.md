# 数据库设计

> 返回 [需求文档索引](./需求文档.md)

使用 SQLite。库内分两类表：

- **业务表（8 张）**：供 Agent NL2SQL 分析（及 admin 受控写），进入 Schema Linking
- **应用表**：账号、Session、长期记忆；**默认不进入** Schema Linking / NL2SQL；Guardrail 禁止业务 SQL 访问

## 0. 应用表

### 0.1 app_users（应用账号）

字段：

- id
- username
- password_hash
- role（`analyst` | `admin`）
- created_at

说明：

- 仅由 `/api/auth/*` 读写
- Guardrail 禁止业务 SQL 访问或修改本表
- `admin` 注册需校验环境变量邀请码，邀请码不入库

### 0.2 chat_sessions（会话）

字段：

- id（即 `session_id`）
- user_id（关联 `app_users.id`）
- title（可选，首问摘要）
- created_at
- updated_at

### 0.3 session_turns（Session 工作记忆 / 多轮槽位）

字段：

- id
- session_id
- turn_index
- question
- intent
- sql_text
- metrics_json（如 `["gmv"]`）
- time_range_json
- filters_json
- group_by_json
- result_summary
- created_at

要求：

- 按 `session_id` 隔离；每个 session 保留最近 N 轮（默认 10，超出淘汰最旧）
- 追问时读取该 session 最近一轮槽位做合并

### 0.4 user_preferences（跨 Session 偏好，单行 JSON）

字段：

- user_id（PK，关联 `app_users.id`）
- preferences_json
- updated_at

`preferences_json` 建议结构（可缺省字段）：

```json
{
  "default_time_range": "last_30d",
  "preferred_dimensions": ["channel", "province"],
  "preferred_chart_types": ["bar", "line"],
  "metric_overrides": {
    "gmv": "orders.pay_amount"
  }
}
```

说明：不做向量检索；整份 JSON 读写即可。角色以 `app_users.role` 为准，不必写入偏好。

### 0.5 user_analysis_summaries（跨 Session 最近摘要列表）

字段：

- id
- user_id
- session_id
- question_summary
- answer_summary
- metrics_json
- filters_json
- created_at

要求：

- 按 `user_id` 隔离；每用户保留最近 M 条（建议默认 20）
- 一轮分析成功结束后追加一条（可异步）；读取时取最近若干条注入上下文
- **禁止**写入姓名、手机、邮箱、身份证等敏感明文
- 检索方式：按 `user_id` 取最近列表，可选再按 intent/metric 关键词过滤；**不做 embedding**

## 1. users（业务用户，不是登录账号）

字段：

- id
- name
- phone
- email
- id_card
- city
- province
- gender
- age_group
- register_date

## 9. 数据要求

- 业务表生成不少于 1000 条模拟数据
- 时间跨度覆盖最近 180 天
- 包含多个渠道、城市、品类、支付方式、退款原因
- 数据能支持 GMV、订单量、退款率、转化率、客单价、利润率等分析
- 可预置 1 个演示用 `analyst` 账号；`admin` 通过邀请码注册或文档说明创建方式
- 初始化时创建应用表（`app_users` / `chat_sessions` / `session_turns` / `user_preferences` / `user_analysis_summaries`），可无大量种子数据
